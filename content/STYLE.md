# 개념 노트 집필 규약

과목별 집필자 5명이 **동일하게** 따른다. 문체가 갈리면 한 사람이 쓴 교재로 읽히지 않는다.

---

## 0. 이 노트는 무엇인가

시험 직전에 폰으로 읽는 **압축 정리**다. 교과서가 아니다.

- 독자는 비전공자일 수 있고, 대개 출퇴근길에 한 손으로 읽는다.
- 목표는 "이해했다"가 아니라 **"이 문제가 나오면 고를 수 있다"** 이다.
- 그래서 모든 절이 기출과 연결돼야 한다. 기출에 안 나오는 내용은 쓰지 않는다.

## 1. 파일

```
content/s{과목번호}/{concept-id}.md
```
`concept-id` 는 배정표의 개념명을 kebab-case 로 옮긴 영문 슬러그다 (`객체지향` → `oop`).
한글 파일명 금지. 슬러그는 프론트 URL(`#/concepts/oop`)에 그대로 박힌다.

## 2. 프론트매터 (전부 필수)

```yaml
---
id: db-normalization
subject: 3
title: 정규화와 이상 현상        # 화면에 뜨는 이름. 한글
tier: S                          # 배정표 값 그대로
tags: [정규화, 이상현상, 1nf, 2nf, 3nf, bcnf, 부분함수종속, 이행함수종속]
keywords: [정규화]               # ★ 배정표의 개념명. kw: 태그와 정확히 일치해야 관련 기출이 붙는다
items: [q:2024-1:037, q:2023-2:044]   # 수동 pin. 배정표 sample_items 에서 고른다
updated: 2026-08-15
---
```

`keywords` 를 틀리면 **관련 기출이 한 건도 안 붙는다.** 배정표 문자열을 그대로 복사하라.

## 3. 본문 구조 — 이 순서를 지킨다

```markdown
## 한 줄 정의
(한 문장. 여기만 읽고 넘어가도 손해가 없어야 한다)

## 왜 시험에 나오나
(1~2문장. 출제 빈도와 어떤 각도로 나오는지)

## 그림
(인라인 SVG 하나. §5 참조)

## 핵심
(표 또는 3~6개 불릿. 여기가 본체다)

## 헷갈리는 지점
(오답을 유도하는 지점. **최소 2개.** 이 절이 이 노트의 존재 이유다)

## 기출 패턴
(실제로 어떻게 물어보는지 2~3줄. 배정표 sample_items 를 읽고 쓴다)
```

분량은 **600~1,100자**. 넘으면 개념을 쪼갤 신호다.

## 4. 문체

- 평서형 종결(`~이다`, `~한다`). 존댓말·구어체 금지. (AI 설명 패널만 존댓말을 쓴다 — 역할이 다르다)
- 한 문장 = 한 사실. 접속사로 문장을 잇지 않는다.
- 영문 약어는 첫 등장에 풀어 쓴다: `정규화(Normalization)`, `DDL(Data Definition Language)`.
- **"매우", "중요한", "반드시 알아두자" 같은 말을 쓰지 않는다.** 중요하면 중요한 내용을 쓰면 된다.
- 독자를 부르지 않는다(`여러분`, `우리`). 시험 얘기를 할 때만 2인칭이 허용된다.
- 숫자·연도·규격은 기출에서 확인한 것만 쓴다. **모르면 쓰지 않는다.** 지어낸 수치는 학습에 독이다.

## 5. 그림 — 인라인 SVG를 직접 쓴다

빌드 단계에 다이어그램 라이브러리를 두지 않는다. SVG 를 손으로 쓴다.

```svg
<svg viewBox="0 0 400 160" role="img" aria-label="정규화 단계">
  <rect x="10" y="20" width="80" height="40" rx="6"
        fill="none" stroke="currentColor" stroke-width="1.5"/>
  <text x="50" y="45" text-anchor="middle" font-size="13" fill="currentColor">1NF</text>
  ...
</svg>
```

규칙:
- **색은 `currentColor` 만.** 하드코딩한 색은 다크모드에서 안 보인다. 강조가 필요하면 `opacity` 로.
- `viewBox` 필수, `width`/`height` 속성 금지 (반응형이 깨진다).
- 폭 400 이하 기준으로 그린다. 폰에서 375px 안에 들어가야 한다.
- `font-size` 는 12 이상. 그보다 작으면 폰에서 못 읽는다.
- `role="img"` + `aria-label` 필수.
- 외부 폰트·이미지·스크립트 금지.

그림이 개념을 **설명하지 못하면 넣지 않는다.** 장식용 도형은 지면 낭비다.
표로 충분한 것은 표로 쓴다(비교·분류는 대개 표가 낫다).

## 6. 미니 퀴즈

프론트매터 아래, 본문 끝에 둔다.

```markdown
## 퀴즈
- q: 부분 함수 종속을 제거하면 몇 정규형인가?
  choices: [1NF, 2NF, 3NF, BCNF]
  a: 2
  why: 부분 함수 종속 제거가 2NF 의 정의다. 3NF 는 이행 함수 종속 제거다.
```

- 개념당 **2~3문항**.
- 기출 문항을 베끼지 않는다. 저작권 문제이기도 하고, 관련 기출은 어차피 따로 붙는다.
- `why` 는 정답 근거 + **오답 하나가 왜 틀렸는지**를 함께 쓴다.
- 보기 4개, `a` 는 1-based.

## 7. 하지 말 것

| 금지 | 이유 |
|---|---|
| 기출 지문·보기를 그대로 옮겨 쓰기 | 저작권. 관련 기출은 id 로 연결된다 |
| 확인 안 된 수치·연도 | 틀린 암기는 안 배운 것보다 나쁘다 |
| 다른 과목 소유 개념 집필 | 배정표에 소유자가 있다. 필요하면 `[[개념id]]` 로 링크만 |
| 마크다운 h1(`#`) | 제목은 프론트매터 `title` 이 담당한다 |
| 코드블록 안에 정답 힌트 | 코드는 예시 목적으로만 |

## 8. 용어 표기 사전 (5명 공통)

| 쓴다 | 안 쓴다 |
|---|---|
| 데이터베이스 | DB, 디비 |
| 릴레이션 | 테이블(관계형 모델 설명 시) |
| 소프트웨어 | SW, 에스더블유 |
| 트랜잭션 | 트렌젝션, 트랜색션 |
| 스케줄링 | 스케쥴링 |
| 인터페이스 | 인터페이시스 |
| 알고리즘 | 알고리듬 |
| 애플리케이션 | 어플리케이션, 앱(문어체에서) |
| 오류 | 에러(본문에서. 코드 주석은 허용) |
| 프로세스 | 프로세싱(문맥이 다르면 구분) |

외래어는 국립국어원 표기를 따른다. 확신이 없으면 영문 원어를 괄호에 병기한다.
