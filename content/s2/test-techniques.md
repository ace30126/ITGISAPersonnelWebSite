## 한 줄 정의

화이트박스 테스트는 프로그램 내부 구조를 보고 경로를 점검하는 기법이고, 블랙박스 테스트는 내부를 보지 않고 입력에 대한 출력만 확인하는 기법이다.

## 왜 시험에 나오나

2과목 상위 출제군이다. 기법 이름을 둘 중 어느 쪽으로 분류하는지만 물어보는 문항이 회차마다 반복된다.

## 핵심

| 화이트박스 기법 | 블랙박스 기법 |
|---|---|
| 기초 경로 검사 | 동치 분할 검사 |
| 조건 검사 | 경계값 분석 |
| 루프 검사 | 원인-효과 그래프 검사 |
| 데이터 흐름 검사 | 오류 예측 검사, 비교 검사 |

- 화이트박스 테스트는 논리 흐름도를 이용하고, 테스트 데이터를 선택하기 위해 검증 기준을 정한다.
- 화이트박스 테스트는 실제로 프로그램을 실행해 오류를 찾으므로 동적 테스트에 해당한다.
- 블랙박스 테스트는 프로그램의 구조를 고려하지 않고 요구나 명세를 기준으로 테스트 케이스를 만든다.
- 테스트 케이스에는 시험 조건, 테스트 데이터, 예상 결과가 들어간다.

## 헷갈리는 지점

- 경계값 분석은 블랙박스다. 화이트박스 대표 기법으로 기초 경로 검사와 경계값 분석을 나란히 적은 보기는 틀렸다.
- 기초 경로 검사는 화이트박스다. 블랙박스 기법 묶음에 끼워 넣는 문항이 반복된다.
- 프로그램의 구조를 고려하지 않는 쪽은 블랙박스다. 이 문장을 화이트박스 설명에 붙이면 틀린 보기가 된다.
- 반복 조건을 만족하는데도 루프 안 문장이 실행되지 않는 오류는 블랙박스로 찾지 못한다. 내부 경로를 봐야 보인다.
- 이름에 그래프가 들어가도 원인-효과 그래프 검사는 블랙박스다. 제어 흐름 그래프와 헷갈리게 배치된다.

## 기출 패턴

기호로 나열한 기법 여섯 개 중 화이트박스만 짝지으라는 형태가 굳어져 있다. 단답형은 "블랙박스 기법으로 거리가 먼 것"을 묻고 기초 경로 검사를 정답으로 둔다. 설명형은 화이트박스의 특성 넷 중 하나를 블랙박스 설명으로 바꿔 틀린 것을 찾게 한다.

## 퀴즈
- q: 블랙박스 테스트 기법에 해당하는 것은?
  choices: [경계값 분석, 조건 검사, 기초 경로 검사, 루프 검사]
  a: 1
  why: 경계값 분석은 입력 조건의 경계에서 테스트 케이스를 뽑는 블랙박스 기법이다. 조건 검사와 루프 검사는 내부 제어 구조를 보는 화이트박스 기법이다.
- q: 화이트박스 테스트에 대한 설명으로 틀린 것은?
  choices: [모듈의 논리적 구조를 점검한다, 논리 흐름도를 이용할 수 있다, 프로그램 구조를 고려하지 않는다, 검증 기준을 정해 테스트 데이터를 고른다]
  a: 3
  why: 구조를 고려하지 않는 것은 블랙박스 테스트의 특성이다. 화이트박스는 내부 구조를 알고 경로를 설계하므로 정반대다.
- q: 블랙박스 테스트로 발견하기 어려운 오류는?
  choices: [비정상 입력에 오류 처리를 하지 않는 경우, 정상 입력에 기능이 수행되지 않는 경우, 반복 조건을 만족해도 루프 내 문장이 실행되지 않는 경우, 경계값 입력에 기대한 출력이 나오지 않는 경우]
  a: 3
  why: 루프 내부의 문장 실행 여부는 코드 경로를 봐야 확인되므로 화이트박스의 영역이다. 경계값 입력 결과는 출력만 보면 되므로 블랙박스로 확인된다.
