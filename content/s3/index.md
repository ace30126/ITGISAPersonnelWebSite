## 한 줄 정의

인덱스(Index)는 데이터를 빠르게 찾기 위해 테이블과 별도로 만들어 두는 색인 구조다.

## 왜 시험에 나오나

인덱스 설명 넷 중 틀린 것을 고르는 문항이 3과목에 꾸준히 나온다. 생성·삭제 명령어와 뷰와의 관계 두 지점에서 답이 갈린다.

## 핵심

- 사전의 색인처럼 원하는 값의 위치를 먼저 찾아 검색 속도를 높이는 자료 구조다.
- 생성은 CREATE INDEX, 제거는 DROP INDEX 다. 인덱스도 [[db-ddl-dml-dcl]]의 DDL 이 다룬다.
- 테이블과 클러스터에 연관되며 독립적인 저장 공간을 가진다.
- 테이블을 삭제하면 그 테이블의 인덱스도 함께 삭제된다.
- BETWEEN 같은 범위 검색에도 쓰인다.
- 사용자가 필요에 따라 만들고 지울 수 있다.

## 헷갈리는 지점

- 인덱스의 추가·삭제 명령은 ADD 와 DELETE 가 아니다. CREATE 와 DROP 이다. 이 한 줄을 틀린 서술로 넣은 문항이 반복된다.
- 인덱스는 시스템이 자동으로만 만드는 것이 아니다. 사용자가 변경할 수 없다는 서술은 오답이다.
- 뷰(View)는 독자적인 인덱스를 가질 수 없다. "뷰 자체로 인덱스를 가짐"이 뷰의 장점으로 제시되면 그것이 정답이다.
- 인덱스는 검색을 빠르게 하지만 삽입·삭제·갱신에는 부담을 더한다. 모든 연산이 빨라진다는 서술은 성립하지 않는다.
- 역정규화, 트리거, 트랜잭션과 함께 보기로 깔린다. "조회를 빠르게 하려고 독립적인 저장 공간을 갖는 것"이라는 지문이면 답은 인덱스다.

## 기출 패턴

옳지 않은 것을 고르는 형태가 대부분이고, 명령어를 ADD·DELETE 로 바꿔 놓은 보기가 정답이다. 뷰 문항에서는 인덱스가 반대 방향의 함정으로 쓰인다. 뷰는 인덱스를 가질 수 없다는 사실을 뒤집은 보기가 답이 된다. 성능 관련 구성 요소를 묻는 지문이 나오면 인덱스와 역정규화가 나란히 보기로 등장한다.

## 퀴즈
- q: 인덱스에 대한 설명으로 옳지 않은 것은?
  choices: [검색 속도를 높이기 위한 자료 구조다, 추가와 삭제 명령은 각각 ADD 와 DELETE 다, 범위 검색에 활용될 수 있다, 테이블을 삭제하면 함께 삭제된다]
  a: 2
  why: 인덱스는 CREATE INDEX 로 만들고 DROP INDEX 로 지운다. 테이블과 함께 삭제된다는 서술은 대부분의 데이터베이스에서 맞는 동작이다.
- q: 뷰의 장점으로 볼 수 없는 것은?
  choices: [뷰 자체로 인덱스를 가짐, 데이터 보안 용이, 논리적 독립성 제공, 사용자 데이터 관리 용이]
  a: 1
  why: 뷰는 독자적인 인덱스를 가질 수 없다. 보안과 논리적 독립성은 뷰를 쓰는 대표적인 이유라 장점이 맞다.
- q: 테이블과 클러스터에 연관되어 독립적인 저장 공간을 가지며 조회를 빠르게 하는 것은?
  choices: [인덱스, 트리거, 역정규화, 트랜잭션]
  a: 1
  why: 별도 저장 공간을 갖는 색인 구조가 인덱스다. 역정규화도 조회 성능을 노리지만 테이블 구조 자체를 바꾸는 설계 기법이라 저장 공간을 따로 두지 않는다.
