## 한 줄 정의

스키마(Schema)는 데이터베이스의 구조와 제약 조건을 정의한 명세이며, 보는 관점에 따라 외부·개념·내부 세 단계로 나뉜다.

## 왜 시험에 나오나

스키마 이름을 설명으로 골라내는 문항과, 설계 단계별로 수행 작업을 갈라내는 문항이 붙어 다닌다. 어느 작업이 어느 단계에 속하는지가 답을 가른다.

## 핵심

| 스키마 | 내용 |
|---|---|
| 외부 스키마 | 사용자나 응용별로 필요한 부분만 본 관점. 여러 개 존재 |
| 개념 스키마 | 데이터베이스 전체를 정의한 것. 개체, 관계, 제약 조건, 접근 권한, 무결성 규칙을 명세. 하나만 존재 |
| 내부 스키마 | 물리적 저장 구조와 접근 경로 |

| 설계 단계 | 수행 작업 |
|---|---|
| 개념적 설계 | 개체 관계도 작성, DBMS 에 독립적인 개념 스키마 설계 |
| 논리적 설계 | 목표 DBMS 에 맞는 논리 구조로 사상, 트랜잭션 인터페이스 설계, 스키마 평가와 정제, [[db-normalization]] |
| 물리적 설계 | 저장 레코드 양식 설계, 접근 경로 설계, 레코드 집중의 분석 |

## 헷갈리는 지점

- 개념 스키마는 데이터베이스 전체 하나뿐이고 외부 스키마는 여러 개다. 개수를 바꿔 놓은 서술이 오답이다.
- 트랜잭션 인터페이스 설계는 논리적 설계의 작업이다. 개념적 설계나 물리적 설계 항목으로 제시되면 그것이 정답이다.
- 스키마의 평가 및 정제는 논리적 설계다. 물리적 설계 고려 사항 문항에서 이 보기가 정답 자리로 나온다.
- 레코드 집중의 분석 및 설계는 물리적 설계다. 논리적 설계 작업을 묻는 문항에서 이 보기가 정답이 된다.
- 응답 시간, 저장 공간 효율, 트랜잭션 처리량은 모두 물리적 설계의 고려 사항이다.

## 기출 패턴

"데이터베이스 전체를 정의하고 제약 조건과 무결성 규칙을 명세한 것"이라는 지문이면 개념 스키마다. 설계 단계 문항은 옳은 작업 셋에 다른 단계의 작업 하나를 섞어 "아닌 것"을 고르게 한다. 스키마와 도메인, 인덱스를 정의하는 명령을 묻는 문항의 답은 CREATE 다.

## 퀴즈
- q: 데이터베이스 전체를 정의하며 개체와 관계, 제약 조건, 무결성 규칙을 명세한 스키마는?
  choices: [개념 스키마, 내부 스키마, 외부 스키마, 내용 스키마]
  a: 1
  why: 전체를 하나로 정의한 것이 개념 스키마다. 외부 스키마는 사용자별 부분 관점이라 전체를 담지 않는다.
- q: 물리적 설계 단계의 고려 사항이 아닌 것은?
  choices: [스키마의 평가 및 정제, 응답 시간, 저장 공간의 효율화, 트랜잭션 처리량]
  a: 1
  why: 스키마 평가와 정제는 논리적 설계의 작업이다. 나머지 셋은 저장과 성능에 관한 것이라 물리적 설계에 속한다.
- q: 개념적 설계 단계에 대한 설명으로 옳지 않은 것은?
  choices: [개체 관계도를 산출물로 만들 수 있다, DBMS 에 독립적인 스키마를 설계한다, 트랜잭션 인터페이스를 설계한다, 논리적 설계의 앞 단계다]
  a: 3
  why: 트랜잭션 인터페이스 설계는 논리적 설계의 작업이다. 개념적 설계는 DBMS 를 정하지 않은 상태에서 개체와 관계를 잡는 단계다.
